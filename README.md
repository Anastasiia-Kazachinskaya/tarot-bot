# AI Tarot Bot

Telegram-бот «личный AI-таролог»: пользователь выбирает расклад, решает,
использовать ли перевёрнутые карты, задаёт вопрос — бот тянет карты из
колоды Таро Райдера—Уэйта, собирает их в одну картинку расклада и
отправляет карты вместе с вопросом в LLM, которая даёт живую
интерпретацию (а не просто пересказывает справочное значение карт).
Каждое чтение сохраняется и доступно позже в истории.

## Как это работает

1. `/start` → бот предлагает выбрать расклад (1, 3, 5, 7 или 10 карт).
2. Пользователь выбирает, использовать ли перевёрнутые карты.
3. Пользователь пишет свой вопрос текстом.
4. Бот вытягивает карты, собирает их в одну картинку расклада и
   отправляет её, затем отправляет запрос в LLM (с учётом позиций,
   переворотов и специальных правил конкретного расклада) и присылает
   интерпретацию.
5. Чтение сохраняется в базу; из клавиатуры под ответом можно начать
   новый расклад (`/reset` работает так же) или открыть историю
   прошлых чтений.

Диалог держится на FSM (`aiogram.fsm`) и рассчитан на одно чтение за раз:
после ответа состояние сбрасывается, для следующего вопроса нужно снова
нажать `/start`, `/reset` или кнопку «Новый расклад».

## Структура проекта

```
bot.py            — обработчики Telegram-бота, FSM-состояния, история чтений
keyboards.py      — инлайн-клавиатуры (выбор расклада, переворот, история и т.д.)
states.py         — состояния диалога (choosing_spread, choosing_reversed,
                    waiting_for_question, processing, follow_up,
                    waiting_for_note)
database.py       — SQLite-хранилище (tarot.db): чтения, дневник,
                    настройки пользователя и дневные лимиты
tarot/
  cards.json      — колода из 78 карт (имя, аркан, масть, прямое/перевёрнутое значение)
  deck.py         — загрузка колоды, вытягивание карт, сборка расклада, путь к картинке карты
  spreads.py      — описания раскладов (позиции карт)
  renderer.py     — сборка карт расклада в одну картинку (Pillow), своя раскладка под каждый тип
  images/rider_waite/ — изображения карт колоды Райдера—Уэйта
  rendered/       — временные картинки расклада (генерируются и удаляются на лету, в git не попадают)
llm/
  cloudru.py      — интерпретация через Cloud.ru (GigaChat) — используется ботом,
                    промпт дополняется специальными правилами под каждый расклад
  gemini.py       — интерпретация через Google Gemini (альтернативный клиент,
                    сейчас не подключён к bot.py, используется только в test_gemini.py)
test_cloudru.py   — ручной скрипт для проверки промпта Cloud.ru (дёргает реальный API)
test_gemini.py    — ручной скрипт для проверки Gemini (дёргает реальный API)
test_renderer.py  — ручной скрипт для проверки сборки картинки расклада
test_images.py    — ручной скрипт для проверки соответствия карт и файлов изображений
```

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Переменные окружения

Создайте файл `.env` в корне проекта:

```env
BOT_TOKEN=       # токен Telegram-бота от @BotFather
DAILY_READINGS_LIMIT=10   # раскладов на пользователя в сутки (0 — без лимита)
DAILY_LLM_LIMIT=30        # обращений к модели в сутки: расклады + уточнения
UNLIMITED_USER_IDS=       # Telegram ID без лимита, через запятую
ADMIN_USER_IDS=           # кому доступна команда /admin со сводкой
GEMINI_API_KEY=  # ключ Google Gemini API (нужен только для llm/gemini.py и test_gemini.py)
CLOUD_API_KEY=   # ключ Cloud.ru Foundation Models (используется ботом по умолчанию)
```

## Запуск

```bash
python3 bot.py
```

Бот стартует поллингом (`dp.start_polling`); при старте инициализируется
`tarot.db` (создаётся таблица `readings`, если её ещё нет).

## Команды

```
/start    — главное меню
/new      — новый расклад
/card     — значение карты без расклада: /card Башня, /card 10 мечей
/history  — история раскладов
/stats    — дневник: статистика и частые карты
/about    — о боте
/help     — помощь
/reset    — сбросить текущий расклад
```

## История

История листается по 10 раскладов на страницу (`HISTORY_PAGE_SIZE`
в `bot.py`), кнопками «← Новее» и «Раньше →». Нумерация сквозная:
`#1` — самый свежий расклад.

## Дневник

Заметка и отметка «отозвалось / мимо» хранятся прямо в таблице
`readings` (колонки `note` и `resonance`, добавляются автоматически при
старте, если их ещё нет). Кнопки появляются под раскладом, открытым из
истории; в списке истории расклады с заметкой или отметкой помечены
значком. `/stats` считает число раскладов, заметок, отметок и самые
частые карты.

## Кто пользуется ботом

Таблица `users` хранит Telegram ID, имя и username тех, кто писал боту,
и время последней активности — обновляется middleware на каждом
сообщении и нажатии кнопки. Команда `/admin` (только для
`ADMIN_USER_IDS`) показывает число людей, раскладов и запросов к
модели, разбивку по типам раскладов и список людей с их активностью.
Содержимое вопросов и интерпретаций в сводку не попадает. Остальным
`/admin` не отвечает вовсе.

## Лимиты

Чтобы расходы на токены не зависели от того, сколько людей пользуется
ботом, каждый запрос к модели считается в таблице `usage` (по
пользователю и дню). Лимитов два: на расклады и на все обращения к
модели вместе с уточняющими вопросами и уточняющими картами. Значения
задаются в `.env` (`DAILY_READINGS_LIMIT`, `DAILY_LLM_LIMIT`, 0 отключает
лимит), а `UNLIMITED_USER_IDS` перечисляет тех, на кого он не
распространяется. Запрос засчитывается **до** обращения к модели: платим
за попытку, а не за удачный ответ. История, дневник и `/card` лимитом не
ограничены — они не ходят в LLM.

## Заметки

- LLM-провайдер, который реально дёргает бот — `llm/cloudru.py`
  (модель `ai-sage/GigaChat3.5-432B-A28B`). `llm/gemini.py` реализован
  полностью и включает ретраи на 503, но пока не используется в `bot.py`.
- Блокирующие операции (сборка картинки через Pillow, запросы к SQLite,
  запрос к LLM) вызываются из асинхронных хендлеров через
  `asyncio.to_thread`, чтобы не блокировать event loop бота.
- Картинка расклада на каждый запрос сохраняется во временный файл с
  уникальным именем (`tarot/rendered/<uuid>.jpg`) и удаляется сразу после
  отправки пользователю — это исключает гонку между параллельными
  запросами разных пользователей.
- Метрики по каждому запросу (время вытягивания карт, время ответа LLM,
  время отправки в Telegram) пишутся одной строкой через `logging`;
  при ошибках в лог попадает traceback.
- Все сообщения с разметкой отправляются в режиме HTML: ответ LLM и текст
  пользователя экранируются, из Markdown распознаются `**жирный**` и
  `### заголовки`. Длинный ответ режется на несколько сообщений уже после
  форматирования, с учётом заголовка и подсказки, чтобы не упереться
  в лимит Telegram в 4096 символов; теги `<b>`/`<i>` на разрыве
  закрываются и открываются заново.
- Пока бот ждёт ответ модели, в чате показывается «печатает…».
- У запроса к Cloud.ru таймаут 60 секунд и до трёх попыток на сетевых
  ошибках; если ответ упёрся в лимит токенов, недописанный хвост
  обрезается до последнего полного предложения с пометкой.
- В уточняющие вопросы уходят только последние три пары «вопрос — ответ»
  (`MAX_HISTORY_TURNS` в `llm/cloudru.py`), иначе запрос разрастается.
- Настройка «перевёрнутые карты» хранится в таблице `user_settings`
  (`tarot.db`): выбор по ходу первого расклада запоминается
  автоматически, а режим «спрашивать каждый раз» из меню настроек
  этим выбором не перезатирается.
- Состояние FSM живёт в памяти (`MemoryStorage`), поэтому после
  перезапуска бота уточняющие вопросы и повтор интерпретации
  для старых раскладов больше не работают — бот об этом сообщает.
